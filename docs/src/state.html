A scene is a folder. The files in it are the only state: there is no manifest and no database of gausser's own. Knowing which file means what explains every decision gausser run makes.

Folder layout

Generated from the Scene class (scene.py). Relative to the scene folder.

How a step writes

  1. The step takes the scene lock (.gausser/lock, an flock). A second command fails at once: Another gausser command is already working on …
  2. It works in .gausser/tmp/<step>-<time>/.
  3. On success it replace()s the staged folder into place (remove the old, rename the new) and deletes what was built from the old output.
  4. On failure the staging folder stays for inspection; the previous output is untouched. gausser status shows how much .gausser/tmp/ holds; delete it when nothing runs.

status, view, orbit, monitor and align take no lock: they only read, or only add a new run folder. The lock file names its holder (pid, command line, start time), which the monitor reads.

What a change deletes

✕ deleted · ○ out of date (rebuilt by the next run) · new written. ¹ not when the model was solved with --no-masks (sparse/no-masks). ² only in a 360° scene, where the operator mask also masks COLMAP's features. A new solve also drops the crop box, which lives in sparse/. runs/ is never deleted.

Why delete instead of mark: a stale COLMAP model or dense cloud that silently survives a frame change gives a wrong splat that looks plausible. Deleting makes the next run rebuild it.

Folder modification times are never used: Finder's .DS_Store writes change them.

History, logs and the scene index

Every locked step runs inside Scene.step(). It appends a start and an end record (ok, error or interrupted, and the run folder it made) to .gausser/history.jsonl, and copies everything printed, tool output included, into .gausser/logs/<time>-<step>.log. On a terminal, tools run in a pseudo-terminal so their progress bars still draw. Nothing in the pipeline reads these files; the monitor does.

Each record also goes to the index of all scenes, ~/.local/share/gausser/history.jsonl (GAUSSER_HOME moves it), which is how one monitor serves every scene.

Keeping the Mac awake

Locked commands start caffeinate -i -s -w PID, so a sleeping Mac does not pause training. Closing a laptop's lid still sleeps it unless an external display is attached.
