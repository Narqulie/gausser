# Gausser Studio distributable bundle plan

## Decision scope

Gausser Studio is currently an ad-hoc-signed **developer bundle**. Its launcher
uses the developer's active Pyenv `gausser-engine`, while COLMAP, Brush, FFmpeg,
Node tooling, Python packages, and SAM weights remain machine dependencies.
This plan describes the separate product needed for an offline-capable,
Developer-ID-signed and notarized distribution. It does not alter the Python
engine/SwiftUI ownership boundary.

The target is a signed `.app` and drag-install `.dmg` for macOS 15+, which can
run the locally supported full pipeline after the user explicitly downloads SAM
weights under Meta's authenticated upstream terms.

## Non-negotiable boundaries

- SwiftUI remains a JSON-lines client; the embedded Python engine remains the
  sole owner of commands, manifests, subprocesses, validation, and cancellation.
- All bundled executables are immutable at runtime. Caches, model weights,
  generated bytecode, and user data live under Application Support or scene
  storage, never inside `Gausser Studio.app`.
- Every shipped Mach-O executable, framework, Python extension, dylib, and
  helper is signed explicitly from the innermost component outward. `--deep` is
  verification-only, not a signing strategy.
- SAM3 model weights are **not** bundled. First use must provide a clear
  authenticated-download action and retain no credentials in manifests or logs.
- Msplat remains visibly unmasked and requires its existing acknowledgement;
  its package/Metal requirements must pass the same clean-machine validation as
  every other bundled stage.

## Delivery gates

### 1. Produce a machine-readable dependency closure

Create `macos/distribution/dependencies.json` from a build-time audit. It must
record exact version, license/source URL, architecture, executable path, and
whether an item is required or optional for:

| Capability | Closure to verify |
| --- | --- |
| Engine | Python runtime, Gausser packages, console entry points and native wheels |
| Sharp Frames | `sharp-frames`, FFmpeg/FFprobe and Python package closure |
| SAM3 | SAM3/Torch runtime; model weights remain an explicit post-install download |
| COLMAP | command binary and all Qt/Ceres/SQLite/image-codec dynamic dependencies |
| Brush | native Brush executable and its dynamic runtime closure |
| Msplat | package/native backend closure and Metal runtime behavior |
| LOD | `splat-transform` runtime and its Node/JS closure, or a verified standalone executable |
| Viewer | MetalSplatter frameworks already embedded by SwiftPM |

The audit runs against a clean staging root, not Homebrew/Pyenv paths. Any
non-relocatable absolute path is a release blocker.

### 2. Build relocatable stage runtimes

- Embed a pinned arm64 Python runtime in `Contents/Frameworks/Python.framework`
  and create an isolated virtual environment in `Contents/Resources/python`.
- Install Gausser and its Python-only/native dependencies into that environment
  from a locked wheelhouse. Do not copy a workstation Pyenv virtual environment.
- Package COLMAP, Brush, FFmpeg and the selected LOD runtime beneath
  `Contents/Resources/tools/`, each with a generated dependency report.
- Replace the current developer-only launcher with a relocatable launcher that
  sets `PYTHONHOME`, `PYTHONPATH`, `PATH`, `PYTHONPYCACHEPREFIX`, and stage
  tool locations relative to the bundle. It must invoke the same
  `gausser-engine` entry point used by development.
- Keep an explicitly separate developer mode. It may use a local engine but
  must never masquerade as the distributable build.

### 3. Make preflight distribution-aware

Add an engine `runtime_info` request exposing only safe build metadata:
packaged/developer mode, build version, verified component versions, and SAM
weights state. Stage preflight should distinguish:

1. a bundled tool absent or incorrectly signed (packaging defect),
2. optional SAM weights not downloaded (guided user action), and
3. an ordinary scene prerequisite failure.

No Swift-side CLI path construction is permitted; the engine reports its own
runtime state and preserves the existing stage catalog contract.

### 4. Sign, notarize, and distribute

1. Sign all nested code with Developer ID and hardened runtime, adding only
   demonstrated entitlements.
2. Sign the final app with a secure timestamp, then verify code signatures and
   inspect every nested Mach-O signature.
3. Create a versioned DMG, submit with `xcrun notarytool`, wait for acceptance,
   staple the ticket, and assess it offline.
4. Generate a signed SBOM/license notice from `dependencies.json`; fail the
   release if the closure and notice differ.

Apple guidance: Developer ID distribution requires hardened runtime and
notarization; `notarytool` is the supported submission mechanism. See
[Notarizing macOS software](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)
and [Embedding nonstandard code](https://developer.apple.com/documentation/xcode/embedding-nonstandard-code-structures-in-a-bundle).

### 5. Validate a clean-machine release candidate

On a separate macOS 15+ user account or disposable VM with no Homebrew, Node,
Pyenv, local Gausser checkout, or developer tool PATH:

- install and open the stapled DMG while offline;
- initialize/import a disposable scene; run every preflight and resolve every
  stage catalog;
- run a small COLMAP/Brush/LOD smoke workflow and Sharp Frames if FFmpeg is
  bundled; confirm SAM specifically asks for authorized weights;
- confirm cancellation/process cleanup, scene lock behavior, and engine
  relaunch;
- confirm `otool -L`/runtime audits contain no developer-path references;
- validate app, nested signatures, stapled ticket, SBOM/license manifest, and
  uninstall behavior.

## Implementation task list

1. **Audit the current runtime closure** and write the locked dependency
   manifest plus license inventory.
2. **Choose/prototype the relocatable Python strategy** in an isolated staging
   root; prove `gausser-engine --help` with no Pyenv/Homebrew PATH.
3. **Package one external stage end-to-end** (FFmpeg + Sharp Frames is the
   lowest-risk slice) and extend engine runtime reporting/preflight.
4. **Package and validate COLMAP/Brush/Msplat/LOD**, one independently tested
   closure at a time. Resolve licensing/relocatability blockers rather than
   adding PATH fallbacks.
5. **Replace `macos/package-app.sh`** with explicit `developer` and
   `distribution` commands and deterministic staging cleanup.
6. **Add Developer ID signing/notarization automation**, SBOM, license notice,
   and release artifact provenance.
7. **Run clean-machine acceptance** and publish the first notarized candidate.

## Out of scope until approved

- A universal Intel build: the current target is Apple Silicon/macOS 15+.
- Automated SAM-weight download or redistribution of Meta-gated weights.
- Distribution implementation before the dependency audit establishes that
  each upstream component can be legally and technically relocated.
